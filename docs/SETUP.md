## Часть 1. GitHub (все, 5 минут)

1. Зарегистрируйся на https://github.com, если ещё нет аккаунта.
2. Скинь ник в общий чат, тебя добавят в репозиторий.
3. **Сначала войди в свой GitHub** (github.com → Sign in). Без входа приглашение не видно и будет 404.
4. Прими приглашение одним из способов:
   - открой https://github.com/omut-team/omut, сверху жёлтая плашка **You've been invited** → **View invitation → Accept**;
   - или письмо от GitHub на почте → **View invitation**;
   - или колокольчик справа вверху: https://github.com/notifications
5. Если пришло приглашение в организацию **omut-team**, прими и его: https://github.com/orgs/omut-team/invitation
6. Проверка: на https://github.com/omut-team/omut видна вкладка **Settings**. Значит, у тебя полные права. Готово.

## Часть 2. Git и GitHub Desktop (все, 10 минут)

1. Скачай и поставь **Git**: https://git-scm.com/download/win
   Везде жми «Next», ничего не меняй. Git LFS ставится вместе с ним.
2. Скачай и поставь **GitHub Desktop**: https://desktop.github.com
3. Открой GitHub Desktop → **Sign in to GitHub.com** → войди в свой аккаунт.
4. **File → Options → Git**: проверь, что имя и почта как в GitHub.

Кто любит терминал, то же самое делается командами (Win + R → `cmd`):

```bash
git lfs install
git config --global user.name "Имя Фамилия"
git config --global user.email "почта@от.github"
```

## Часть 3. Скачать проект (все, 5 минут)

**Через GitHub Desktop:**
1. **File → Clone repository → вкладка GitHub.com → omut-team/omut**.
2. Local path: `C:\Users\<ты>\Desktop\omut` → **Clone**.
3. Сверху **Current branch** → выбери **dev**.

**Через терминал:**

```bash
cd %USERPROFILE%\Desktop
git clone https://github.com/omut-team/omut.git
cd omut
git checkout dev
```

Проверка: в папке `omut` есть `README.md`, `docs`, `server`, `web`.

## Часть 4. Unity (Илья, Ярослав, Лиза; Ульяне желательно)

**Важно:** у всех должна быть **одна и та же версия Unity**. Иначе проект ломается у всех.

1. Скачай **Unity Hub**: https://unity.com/download и установи.
2. Открой Hub → войди в Unity-аккаунт (или зарегистрируйся) → лицензия **Personal** (бесплатно).
3. Нужная версия: **6000.3.28f1** (Unity 6.3 LTS). Она же записана в `game/ProjectSettings/ProjectVersion.txt`.
4. Hub → **Установки → Установить редактор** → найди **6000.3.28f1** (если её нет в списке, открой https://unity.com/releases/editor/archive, найди 6000.3.28f1 и нажми **Install** / «Открыть в Unity Hub»).
   Модули: **Windows Build Support (Mono)**. Программистам ещё **Visual Studio** (если его нет).
5. Hub → **Проекты → Добавить → Добавить проект с диска** (англ.: Projects → Add → Add project from disk) → выбери папку `omut\game`.
6. Первое открытие идёт долго (5–15 минут), так и должно быть.

Если Unity при открытии пишет про другую версию, **не соглашайся на обновление**, закрой и поставь 6000.3.28f1.

## Часть 5. Для программистов (Илья, Ярослав)

1. Редактор кода: **VS Code** (https://code.visualstudio.com) или **Visual Studio Community**.
2. В VS Code открой папку `omut`. Справа внизу появится «Установить рекомендуемые расширения», жми **Install**. Там Unity, C#, Docker, диаграммы.
3. В Unity: **Edit → Preferences → External Tools → External Script Editor** → выбери VS Code или Visual Studio.

**Сервер и сайт (Docker):**
1. Поставь **Docker Desktop**: https://www.docker.com/products/docker-desktop, запусти и дождись зелёного статуса.
2. В папке `omut`:
   ```bash
   docker compose up --build
   ```
3. Открой http://localhost:8080. Должна быть страница «Омут» и надпись «Сервер работает ✅».
4. Остановить: `Ctrl + C`, потом `docker compose down`.

## Часть 8. Как сдавать работу каждый день

Главное правило: **каждая задача делается в своей ветке, а в общую ветку `dev` попадает только через Pull Request.**
В `main` никто не пушит напрямую: туда тимлид сливает готовый патч.

### Через GitHub Desktop (проще)

**1. Взять задачу.**
Открой [доску задач](https://github.com/orgs/omut-team/projects/1) → своя задача → справа **Assignees → assign yourself** → перетащи карточку в **In Progress**. После слияния PR задача сама закроется, перетащи её в **Done**.

**2. Обновиться.**
GitHub Desktop → **Current branch: dev** → кнопка **Fetch origin / Pull origin**.

**3. Сделать свою ветку.**
**Current branch → New branch** → имя по задаче:
- `feature/boat-movement` (код)
- `art/fish-sprites` (арт)
- `docs/use-case` (документы)
- `fix/inventory-drag` (исправление)

Based on: **dev** → **Create branch**.

**4. Работать.**
Рисуешь, пишешь код, кладёшь файлы в нужные папки. GitHub Desktop сам покажет слева, что изменилось.

**5. Закоммитить.**
Слева внизу пишешь короткое описание, например `art: спрайты карася и окуня` → **Commit to feature/...**.
Коммить небольшими кусками: сделал кусок, коммит.

**6. Отправить.**
Кнопка **Push origin** (или **Publish branch**, если первый раз).

**7. Открыть Pull Request.**
Кнопка **Create Pull Request** → откроется сайт.
- Сверху проверь: **base: dev ← compare: твоя ветка**.
- В описании напиши `Closes #12` (номер своей задачи).
- **Create pull request**.

**8. Проверка.**
Илья (или Ярослав для кода Ильи) смотрит и жмёт **Approve**, затем **Merge**.
Попросили исправить? Исправляешь в той же ветке, коммит, Push, PR обновится сам.

**9. После слияния.**
Переключись на **dev** → **Pull origin**. Для следующей задачи снова с шага 3.

### То же самое через терминал

```bash
git checkout dev
git pull
git checkout -b feature/boat-movement
# ... работаешь ...
git add .
git commit -m "feat: движение лодки с инерцией"
git push -u origin feature/boat-movement
```

Дальше на сайте появится жёлтая плашка **Compare & pull request**: жми и оформляй PR в `dev`.

### Как писать коммиты

| Начало | Когда | Пример |
|---|---|---|
| `feat:` | новая возможность | `feat: заброс удочки по Space` |
| `fix:` | исправление | `fix: леска не рвалась` |
| `art:` | графика | `art: тайлы воды и берега` |
| `sound:` | звук | `sound: плеск и мотор` |
| `docs:` | документы | `docs: диаграмма состояний рыбы` |
| `test:` | тесты | `test: тест-кейсы на трюм` |

## Часть 9. Правила, чтобы ничего не сломать

1. **Перед работой всегда Pull.** Перед открытием Unity тоже.
2. **Общую сцену `Main` трогает только тот, кто её собирает.** Остальные работают в своей сцене `Sandbox_<Имя>`.
3. Объекты делаем **префабами**. Один префаб правит один человек за раз.
4. Файлы `.meta` всегда коммитятся **вместе** со своим файлом.
5. Не коммить папки `Library`, `Temp`, `Logs`, `UserSettings` (они и так скрыты).
6. Не удаляй и не переименовывай чужие файлы без вопроса.
7. Никаких паролей и ключей в репозитории.

### Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| GitHub Desktop пишет про **conflict** | Ничего не жми, напиши в чат, разберём вместе |
| Unity ругается на версию | Значит стоит не та версия, см. часть 4 |
| Закоммитил не в ту ветку | Не пушь, напиши в чат |
| Картинки в проекте розовые / пустые | В терминале в папке проекта: `git lfs pull` |
| Не можешь сделать Push | Проверь, что принял приглашение (часть 1) |

**Никогда** не делай `git reset --hard`, `git push --force` и не удаляй папку проекта, не спросив.
