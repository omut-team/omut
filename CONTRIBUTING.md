# Как мы работаем

## Ветки

```
main     ← только рабочие версии (патчи 0.1, 0.2 ...). Напрямую не пушим.
dev      ← общая ветка разработки. Сюда сливаются все задачи.
feature/<что-делаю>   ← твоя ветка под одну задачу
```

Примеры: `feature/boat-movement`, `feature/fish-sprites`, `docs/use-case-diagram`, `fix/inventory-drag`.

## Порядок работы над задачей

1. Взять задачу в [Issues](https://github.com/Yarik002/omut/issues), назначить себя.
2. Обновить `dev` и сделать от неё свою ветку:
   ```bash
   git checkout dev
   git pull
   git checkout -b feature/boat-movement
   ```
3. Сделать задачу, коммитить небольшими кусками.
4. Отправить ветку и открыть Pull Request **в `dev`**:
   ```bash
   git push -u origin feature/boat-movement
   ```
5. В описании PR написать `Closes #номер_задачи`.
6. Дождаться проверки, после этого PR сливается.

## Коммиты

Коротко и по делу, на русском:

```
feat: движение лодки с инерцией
fix: леска не рвётся при перегрузке
art: спрайты карася и окуня
docs: диаграмма вариантов использования
test: тест-кейсы для трюма
```

## Правила Unity (чтобы не ломать друг другу проект)

1. **Общую сцену `Main` правит только тот, кто её собирает.** Остальные работают в своих тестовых сценах `Sandbox_<Имя>`.
2. Всё, что можно, делаем **префабами**. Префаб правит один человек за раз.
3. Перед тем как открыть Unity, сделай `git pull`.
4. Не коммить папки `Library`, `Temp`, `Logs`, `UserSettings`. Они уже в `.gitignore`.
5. Файл `.meta` всегда коммитится **вместе** со своим файлом.
6. Версия Unity у всех одинаковая (см. [docs/SETUP.md](docs/SETUP.md)).

## Дизайнерам

Правила по размерам, именам и форматам: [docs/ART.md](docs/ART.md).
Картинки и звуки хранятся через Git LFS автоматически, ничего делать не надо.

## Нашёл баг

Создай задачу по шаблону **«Баг»**: что делал, что ожидал, что получилось, скриншот.
